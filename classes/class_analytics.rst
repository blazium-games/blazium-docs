Analytics
=========

**Inherits:** :ref:`Object<class_Object>`

Opt-in analytics singleton for editor demographics and game session events.

.. rst-class:: classref-introduction-group

Description
-----------

**Analytics** queues JSON events and optionally POSTs them to an ingest endpoint. Editor builds compiled with ``editor_analytics=yes`` record demographic/usage events after consent. Export templates compiled with ``analytics=yes`` expose a small game SDK (:ref:`track()<class_Analytics_method_track>`, session start/end).

Editor :ref:`get_app_id()<class_Analytics_method_get_app_id>`, :ref:`get_build_id()<class_Analytics_method_get_build_id>`, and ingest URL are baked at compile time (``editor_app_id``, ``editor_build_id``, ``editor_analytics_endpoint``) and cannot be changed from CLI, environment, or Editor Settings. If ``editor_app_id`` is omitted, the editor uses ``custom_blazium_engine``. If ``editor_build_id`` is omitted, the editor uses the engine git hash. An empty editor ingest URL disables collection and sending (no queue growth). Export templates may optionally bake ``template_app_id``, ``template_build_id``, and ``template_analytics_endpoint``; a non-empty bake locks that field. An empty template analytics URL still means "use Project Settings", not "disable". Consent priority is CLI ``--analytics=``, then ``BLAZIUM_ANALYTICS_CONSENT``, then Editor Settings or :ref:`set_consent()<class_Analytics_method_set_consent>`. Anonymous mode (default) omits ``device_uid``; identified mode sends :ref:`OS.get_unique_id()<class_OS_method_get_unique_id>`. See :ref:`get_resolved_config()<class_Analytics_method_get_resolved_config>`.
